# Design

## Context

- 现状：派生 CSV 只有原始列（`O_str∈[-1,0]`、`S_pi∈[1.5,8]`），两张图色标各异；主 specs 另有 `numerics/string-afm-observables` 与 `viz/string-afm-heatmaps`。见 `proposal.md` 动机。
- 约束（已定）：`O_str_norm=-O_str`（取反，不取绝对值）；`S_pi_norm=S(π)/8`；原始列保留；ZR 链不动。

## Goals / Non-Goals

**Goals:**

- 三张图统一为"序参量强度 ∈[0,1]"语言；归一可审计（线性、无折叠）。

**Non-Goals:**

- 不重跑求解（存档不变）；不动 ZR 数值与图；不改网格与行序契约。

## Decisions

### 1. 取反而非绝对值

归一是原始值的精确线性函数，符号链条不断：若未来某区域出现 `O_str>0`，归一值如实为负而非被折叠。绝对值仅在"只关心有无序"时等价，但会掩盖符号类 bug（如排序约定改错）。与原论文 abs 惯例的差异在 spec 场景"线性无折叠"中锁死。

### 2. 加列而非替换

CSV 保留原始列、新增归一列：审计链（存档→原始值→归一值）可逐段验证；旧列名不变，历史脚本仍可读。列名：`O_str_norm`、`S_pi_norm`。

### 3. 两图统一顺序色标 [0,1]

归一后两图的 0/1 语义一致（0=无序、1=序饱和），用同一顺序色标（viridis）+ 0/1 色棒刻度；不再用发散色标（发散色标的中点 0 在归一语义下无特殊意义）。ZR 图保持发散色标不动——它的 ±1 本身就是符号判据。

## Risks / Trade-offs

- [Risk] 读者把 string 图的 +1 误读为量子化 → Mitigation：spec 只要求"接近 +1（容差 0.05，有限尺寸偏差内）"，不写量子化断言。
- [Risk] ZR 图（-1=拓扑）与 string 图（+1=拓扑）符号语言相反 → Mitigation：各跟各的文献惯例，不强行统一；在三图并排的报告文字中注明。
- [Trade-off] CSV 加列使文件变宽 → 可忽略（10000 行 × 1 列）。

## Migration Plan

- 本增量内完成：derive 脚本加归一列（秒级重跑派生即可，无需求解）、重出两张图；旧图被覆盖（git 可回滚）。
